### 미들웨어 2-레이어 구조 (v0.x 목표)

현재 Koa onion 미들웨어 = 글로벌 전용. v0.x에서 per-plugin interceptor를 추가하여 2-레이어로 확장.

```
요청 흐름:
  → [글로벌 미들웨어: logger, devtools, validator]
    → [per-plugin interceptor: auth, cache, throttle 등]
      → handler
    ← [per-plugin interceptor]
  ← [글로벌 미들웨어]
```

**API 설계 방향:**

```typescript
// 글로벌 미들웨어 (현재, 유지)
createBridge({
  middleware: [logger, devtools], // 모든 요청에 적용
});

// per-plugin interceptor (추가)
const camera = definePlugin('camera', {
  takePhoto: action<TakePhotoPayload, TakePhotoResponse>()
    .use(authRequired) // 이 액션에만 적용
    .use(compressResponse), // 이 액션에만 적용
  pickImage: action<PickImagePayload, PickImageResponse>(), // interceptor 없음
});
```

**글로벌 vs per-plugin 역할 분담:**

| 글로벌 미들웨어     | per-plugin interceptor      |
| ------------------- | --------------------------- |
| logging, timing     | auth, permission check      |
| devtools recording  | response caching            |
| validation (스키마) | throttle, debounce          |
| error formatting    | payload transform, compress |

### DevTools 미들웨어/인터셉터 시각화 설계

2-레이어 미들웨어 구조를 DevTools에서 직관적으로 구분하기 위한 설계.
Chrome Network Timing + React Query DevTools 접이식 상세의 조합.

#### 색상 규칙

- 🔵 파란색 (`#3B82F6`) = Global middleware
- 🟠 주황색 (`#F59E0B`) = Plugin interceptor
- ⬜ 회색 (`#6B7280`) = handler 본체 (실제 네이티브 호출)
- 🟢 초록 = 성공, 🔴 빨강 = 에러, 🟡 노랑 = 캐시 히트 등 short-circuit

#### 리스트 뷰 (타임라인)

메시지 목록에서 한눈에 어떤 레이어를 거쳤는지 뱃지로 표시.
뱃지 개수로 복잡도를 즉시 파악할 수 있음.

```
시간      액션                  레이어                                    소요    상태
─────────────────────────────────────────────────────────────────────────────────
12:01:03  camera.takePhoto      🔵×3  🟠×2                               320ms   ✓
12:01:04  storage.get           🔵×3  🟠×1 cache-hit                       3ms   ✓
12:01:05  location.watch        🔵×3                                     150ms   ✓
12:01:06  biometric.auth        🔵×3  🟠×1                                 —     ✗
```

- `🔵×3` = 글로벌 미들웨어 3개 통과 (logger, devtools, validator)
- `🟠×2` = 플러그인 인터셉터 2개 통과 (auth, compress)
- `cache-hit` = 인터셉터가 handler를 건너뛴 경우 라벨 표시

#### 상세 뷰 — Waterfall Timing (클릭 시 펼침)

개별 요청을 클릭하면 onion 모델의 진입/복귀를 시간축으로 시각화.
각 레이어가 요청(→)과 응답(←) 양쪽에서 얼마나 걸렸는지 보여줌.

```
▾ camera.takePhoto (총 320ms)

  요청 방향 (→)                              응답 방향 (←)
  ─────────────────────────────────────────────────────────
  🔵 logger        ██░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░██   2ms / 1ms
  🔵 devtools      ██░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░██    1ms / 1ms
  🔵 validator     ███░░░░░░░░░░░░░░░░░░░░░░░░░░░░██     5ms / 0ms
  🟠 auth          ████░░░░░░░░░░░░░░░░░░░░░░░░░██       12ms / 0ms
  🟠 compress      █████░░░░░░░░░░░░░░░░░░░░░░██         0ms / 8ms
  ⬜ handler        ██████████████████████████████         280ms
  ─────────────────────────────────────────────────────────

  Payload:  { quality: 0.8 }
  Response: { uri: "file:///photo.jpg", width: 1920, height: 1080 }
```

- 왼쪽(██) = `next()` 호출 전 (요청 방향 처리 시간)
- 오른쪽(██) = `next()` 반환 후 (응답 방향 처리 시간)
- compress는 요청 시 0ms, 응답 시 8ms → 응답을 압축했음을 시각적으로 알 수 있음

#### Short-circuit 케이스 (handler 스킵)

캐시 히트, 인증 실패 등으로 handler까지 도달하지 않은 경우:

```
▾ storage.get (총 3ms) — 🟡 SHORT-CIRCUIT by cache

  🔵 logger        ██░░░░░░░░██   1ms / 1ms
  🔵 devtools      ██░░░░░░░██    1ms / 0ms
  🔵 validator     ██░░░░░░██     0ms / 0ms
  🟠 cache         ████████       0ms — HIT, returned cached value
  ⬜ handler        (skipped)

  Cache Key: "storage.get:token"
  Response:  { key: "token", value: "abc123" } (from cache)
```

```
▾ biometric.auth (총 15ms) — 🔴 REJECTED by auth

  🔵 logger        ██░░░░░██   1ms / 1ms
  🔵 devtools      ██░░░░██    1ms / 1ms
  🔵 validator     ██░░░██     1ms / 0ms
  🟠 auth          ████        8ms — REJECTED: "Permission denied"
  ⬜ handler        (skipped)

  Error: { code: "AUTH_REQUIRED", message: "Permission denied" }
```

#### 필터링

플러그인 네임스페이스(camera, storage, location 등) 기준으로 빠르게 필터링.
Chrome Network Tab의 필터 바와 동일한 UX.

```
필터 바:
┌─────────────────────────────────────────────────────────────────┐
│ [All] [camera] [storage] [location] [biometric] [haptics]       │
│ Status: [All ▾]  Layer: [All ▾]  🔍 검색...                     │
└─────────────────────────────────────────────────────────────────┘
```

- **플러그인 탭**: 등록된 플러그인별 토글 버튼. 복수 선택 가능
- **Status 필터**: pending / success / error / timeout
- **Layer 필터**: global only / plugin interceptor 있는 것만 / short-circuit만
- **텍스트 검색**: 액션명, payload 내용으로 검색

플러그인 목록은 `createBridgeReact({ plugins: [...] })`에서 등록된 플러그인 이름을 자동 수집하여 탭으로 생성. 수동 설정 불필요.

#### 데이터 모델

DevToolsMiddleware가 기록할 각 미들웨어/인터셉터의 실행 정보:

```typescript
interface MiddlewareTrace {
  name: string; // "logger", "auth", "compress"
  layer: 'global' | 'plugin'; // 레이어 구분
  plugin?: string; // plugin 이름 (layer=plugin일 때)
  enterMs: number; // next() 호출 전 소요 시간
  exitMs: number; // next() 반환 후 소요 시간
  shortCircuit: boolean; // handler까지 도달하지 않고 반환했는지
  shortCircuitReason?: string; // "cache-hit", "auth-rejected" 등
}

interface RecordedMessage {
  // 기존 필드...
  action: string;
  payload: unknown;
  response: unknown;
  totalMs: number;
  status: 'pending' | 'success' | 'error' | 'timeout';

  // 추가 필드
  middlewareTrace: MiddlewareTrace[]; // 실행된 모든 미들웨어/인터셉터 기록
  handlerMs: number; // handler 본체 실행 시간
  handlerSkipped: boolean; // short-circuit 여부
}
```

#### 구현 위치

- `MiddlewareTrace` 수집: `MiddlewarePipeline`이 각 미들웨어 실행 시 타이밍 기록
- `RecordedMessage` 확장: `DevToolsMiddleware`가 trace 데이터를 메시지에 첨부
- Waterfall 렌더링: `RequestInspector` 컴포넌트에 타이밍 바 추가
- 리스트 뷰 뱃지: `MessageTimeline` 컴포넌트에 레이어 뱃지 추가

## 장기 비전 — Universal WebView Bridge

v0.0.1 이후의 성장 방향. 현재 아키텍처가 이미 이를 지원하도록 설계됨.

### 확장 로드맵

| 버전       | Client (Web)     | Host (Native)      | 기타                                              |
| ---------- | ---------------- | ------------------ | ------------------------------------------------- |
| **v0.0.1** | React            | React Native       | 첫 릴리스                                         |
| **v0.x**   | + Vanilla JS     |                    | core를 직접 노출, **per-plugin interceptor 추가** |
| **v1.0**   | + Vue            |                    | composable 래핑                                   |
| **v1.x**   | + Svelte         | + Kotlin (Android) | store 래핑 / native SDK                           |
| **v2.0**   | + Angular, Solid | + Swift (iOS)      | native SDK                                        |
| **v2.x**   |                  | + Flutter          | Dart SDK                                          |

### 왜 가능한가

- `@webview-ts/core`가 이미 프레임워크 무관 — React 의존성 없음
- 프로토콜이 JSON over postMessage — 모든 WebView 환경에서 동일
- 클라이언트 추가 = core를 프레임워크 프리미티브로 래핑하는 것뿐
  - Vue: `ref()` + `watch()` + `onMounted()`
  - Svelte: `writable` store
  - Vanilla: core 그대로
- 네이티브 호스트 추가 = 같은 JSON 프로토콜을 해당 언어로 구현
  - Swift: `WKScriptMessageHandler` + `evaluateJavaScript`
  - Kotlin: `WebView.addJavascriptInterface` + `evaluateJavascript`

### 유일한 난관: Cross-language 타입 공유

TS의 `definePlugin` 타입 → Swift/Kotlin 타입으로 자동 생성하는 codegen이 필요.
하지만 v1까지는 불필요 — 네이티브 호스트는 JSON 딕셔너리로 충분하고,
타입 안전성은 TS 쪽에서만 보장하면 됨.

### 포지셔닝

- **Capacitor**: 풀 런타임, 무겁고, 자체 플러그인 생태계
- **@webview-bridge (gronxb)**: 경량이지만 flat (미들웨어/플러그인/DevTools 없음)
- **@webview-ts**: 경량 + 타입 안전 + 미들웨어 + 플러그인 + DevTools = "WebView 브릿지의 tRPC"
